# Этап 4: базовые ящики и хранение на конструкциях

Основа — только официальный HBM X5687, коммит
`23ef33447280d83d44c1f7bcd3853fe59c0ec1fc`. Код других современных HBM-портов
не использован. Это очередная часть инвентарей и начальная интеграция
переносимого хранения с Create, не завершение всех машин этапа 4 плана.

| Исходник X5687 | Реализация 0.4.0 |
|---|---|
| `TileEntityCrateIron` / `TileEntityCrateSteel` | 36 / 54 слота, предел обычного стака 64 |
| `BlockStorageCrate` | Полный блок, исходные верх/низ и боковые текстуры, твёрдость 5, сопротивление 10 |
| `CraftingManager`, строки 273–274 | Исходный крафт `PPP / I I / III`: 3 пластины + 5 слитков соответствующего металла; общие теги `c:plates`, `c:ingots` |
| `ContainerCrateIron`, `ContainerCrateSteel` | Исходные 4/6 рядов и координаты слотов, Shift-клик, общее серверное содержимое |
| `GUICrateIron`, `GUICrateSteel` | Оригинальные GUI-текстуры, размеры 176×186 / 176×222, названия и подсказки |
| `TileEntityCrateBase` | Доступ со всех сторон, ввод/вывод всех слотов, сохранение инвентаря и имени, исходные звуки открытия/закрытия |
| `BlockStorageCrate` comparator | Сигнал по заполненности, 0 для пустого / 15 для полного обычными стаками |
| `ServerConfig.CRATE_KEEP_CONTENTS = true` | Содержимое переносится внутри выпавшего предмета и восстанавливается при установке |

## Современная адаптация

- NBT и компоненты ItemStack 1.21.1 вместо старых `slotN`/`stacklock`. Полное
  перемещение заполненного ящика сохраняет все слоты и компоненты предметов.
  Автоматического переноса миров 1.7.10 нет.
- Обычный пустой ящик складывается до 64, заполненный предмет имеет предел 1.
  После опустошения возвращаются обычные компоненты пустого ящика.
- При разрушении в выживании ящик выдаёт один предмет с содержимым; кирка
  ускоряет добычу, но обязательного инструмента для сохранности содержимого нет.
  При разрушении взрывом также выдаётся заполненный ящик; это не защита уже
  выпавшего предмета от последующих взрывов, огня или других воздействий мира.
- В творческом режиме заполненный ящик выпадает одним предметом, пустой — нет.
  Это явная адаптация по правилам переносимых контейнеров современного Minecraft.
- Ящики и шалкеры не вкладываются друг в друга через обычное меню или автоматизацию;
  правило действует и в движении. Старый предел сжатого NBT 6 kB и случайный
  `stacklock` не воспроизводятся, используются современные компоненты и кодеки.
- Исходные OGG переименованы в нижний регистр для допустимых ResourceLocation.
  Содержимое звуков, текстур и GUI не менялось; хеши — `crate-provenance.json`.
- Для железных пластин исходный рецепт принимает общий тег. В текущем составе
  сборки ему соответствует железный лист Create (`create:iron_sheet`). Новая
  пластина HBM и дублирующий рецепт прессования железа не добавлялись.

## Create 6.0.10

Ящики явно зарегистрированы как тип mounted storage `hbm:storage_crate` через
API Create. При сборке инвентарь копируется в хранилище конструкции; после
разборки её актуальное содержимое заменяет исходное содержимое блока целиком.
Пустые слоты тоже восстанавливаются, поэтому извлечённые в движении предметы
не возвращаются из старого NBT блока.

Для меню на конструкции используется тот же тип меню HBM с фильтром слотов,
предикатом дистанции/жизни конструкции и штатной синхронизацией сервера.
Содержимое доступно общей системе хранения Create; отдельного имитированного
тика машины и параллельного производства нет. Сам ящик — контейнер.

Проверены реальные тики вращения подшипника, вставка/извлечение в движении,
NBT-кодек, поворот на 90°, разборка, а также GUI и действия настоящего клиента
на движущейся конструкции. Физическая пара переносных интерфейсов хранения,
поезда и сложные модпаки разработчиком отдельно не проверялись — см. B11.
Полное закрытие процесса проверено с ящиками после разборки; отдельная ручная
проверка закрытия игры с собранной конструкцией остаётся в B12.

Железная печь всё ещё `create:non_movable`. Её перемещение, обработка рецептов
в движении, сети жидкости/энергии и адаптеры вращения этой обновой не реализованы.

## Оставшаяся часть X5687

Открытие ящика прямо из руки (`CRATE_OPEN_HELD`), замки/ключи/отмычки HBM,
пауки-ловушки и генерация специальных ящиков с добычей не перенесены.
Настройка отключения сохранения содержимого пока не добавлена: используется
основное поведение X5687 с `CRATE_KEEP_CONTENTS = true`. Остальные ящики
(вольфрам, деш, сейф, шаблонный и массовое хранилище) не добавлены.
